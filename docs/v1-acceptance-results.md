## 过程中的问题及处理

- 首次从零构建在 Python 官方包下载阶段超时。增加重试、超时和缓存参数，随后显式使用公开镜像完成构建；没有修改依赖版本。
- 验收脚本先复用现有依赖做流转检查，再切换到从源码重建的应用镜像检查部署与页面。两类证据分别记录，没有把复用依赖称作从零安装。
- 页面检查中最初误用了 `/plans/search/`，实际路径为 `/plan/search/`。验收脚本已使用路由反向解析，未把脚本的错误路径当作平台缺陷。
- 高负载验收期间曾观察到一次原平台就绪探测 503；后续数据库、迁移和缓存检查恢复正常，10 次低并发复测均为 200。没有扩大探测超时或隐藏失败来制造通过结果。
- 开发容器源代码挂载环境仍有 `node_modules` 静态目录提示；独立完整构建镜像的系统检查正常。本轮不将开发挂载结构的提示静默屏蔽。
