# Kiwi TCMS AI 测试平台：竞品对比与优化路线

核对日期：2026-10-03。对象：当前本机 Kiwi 二次开发版本。

## 结论

定位为「面向中小团队的 AI 辅助测试管理平台」更合适：需求与任务单、统一用例库、手工/Web/接口执行、缺陷、报告与回归形成可演示的业务流程。不要把“支持三类测试”说成“支持所有自动化框架”，也不要把菜单数量当作完整度。

本次采用官方公开文档对比加本地源码核对，不是六款产品的付费版本实机测评。功能受版本、授权和部署方式影响，不给出未经验证的性能、市场份额或优劣评分。文档内的“现有”表示找到实现入口，不代表本次完整验收了该模块。

## 二、当前平台差距审视

| 维度 | 当前源码中的能力 | 真实问题/待核验项 | 建议 |
|---|---|---|---|
| 导航与职责 | `web_testing/navigation.py` 已按需求与任务单、测试管理、Web、接口、质量、度量、平台分组 | 不需要反复增加“手工测试”或“闭环”等重复分类 | 保持主菜单稳定；新增能力优先嵌入业务页 |
| 项目上下文 | `project_context.py` 支持切项目留在当前页 | 工作台此前没按所选项目筛选；原生计划/运行搜索未使用会话默认项目 | 本轮修复；继续核验其它原生列表的项目/版本口径 |

| 复用与变更 | Web 环境公共前置登录、数据驱动；手工用例历史与需求变更复核 | 通用业务步骤组件、三类用例一致的版本对比和引用影响提示还需设计 | 下一阶段：版本化公共步骤；历史运行固定引用版本 |

| 计划与执行 | 原生 TestPlan/TestRun；Web/API 套件、运行、结果及归档 | 三种执行各有入口，统一迭代计划的关联与原始执行追踪仍需专项验收 | 用“计划关联执行来源”统一汇总，不复制三种执行配置 |
| 自动化广度 | HTTP 声明式请求/断言；Playwright Chromium 声明式步骤、截图、环境、公共登录 | Web 文档明确暂不支持多浏览器矩阵、录制、Web 定时/CI 触发；外部结果导入也未证明实现 | 优先补 JUnit 结果导入与 Web CI；录制和多浏览器靠后 |
| 缺陷生命周期 | `engineering.py` 有状态迁移、外部状态同步、重复候选、回归验证；已有审计模块 | 接口存在不证明每种外部平台同步都兼容；跨执行方式回归应核对原始证据 | 明确状态与权限；验证修复构建、失败重开；不自动重放有副作用的操作 |
| 报告与门禁 | 报告审批、PDF/HTML 导出、迭代快照、门禁评估及回归入口存在 | 不能把应用内门禁结果说成已阻止外部流水线发布 | 专项验证审批/快照/版本并发；接入流水线后再宣称自动发布门禁 |
| 协作权限 | 项目成员共享部分资产/目录；模型、调用和自动化配置按账号隔离 | 共享目录≠共享凭据；项目角色仍需细化和跨账号专项验收 | 明确读/编辑/执行/审批/凭据使用能力，不直接删除 owner 过滤 |
| 工作台与度量 | 个人需求、计划、未结束运行、AI 任务；质量/趋势已有页面 | 草稿待办遗漏 Web/API；项目与账号统计混用；流程完成度不能等同质量分 | 本轮补三类草稿待办和统计范围；后续增加有明确分母的覆盖/风险指标 |
| AI 可解释性 | 用户模型配置、异步进度、原文依据、人工复核、规则快照、调用记录 | 没有证据支持“生成准确率 xx%”；项目自检的“完整”不能替代真实模型评估 | 建立不含生产隐私的标准需求集，量化修改率、遗漏场景和错误假设 |
| 安全与运维 | 加密配置、任务租约、允许访问目标、快照、代码测试和 CI 文件 | CI 配置存在≠远程 CI 本次已通过；仍缺恢复演练和负载基线 | 演示与生产配置分开；备份恢复、并发测试、站点出网隔离验收 |

## 三、本轮实际实施

1. 工作台需求、手工草稿、个人计划和参与的未结束运行跟随当前项目；选中版本时筛选计划及运行。需求修订号不当作产品发布版本，需求/草稿仍按项目统计。
2. 明确显示统计范围。AI 任务和模型配置仍按账号统计，标签明确标注；项目不存在时显示提示，不能静默扩大到所有项目。
3. Web 与接口待处理 AI 草稿进入工作台待办，并提供复核入口；已导入的草稿不重复计入。
4. 原生计划/运行搜索默认跟随所选项目/版本；用户主动选择“全部项目”仍可覆盖默认值。
5. 三类用例的“全部”页面统一分页，每页 15/30/60 条。排序明确为类型及编号倒序。数据库按页取数据，不把全部自动化配置加载到浏览器。
6. 全选仅当前页，批量归档到同项目共享目录或移出目录；逐条验证可见性及编辑权限，整批原子处理，不能出现部分成功却误报整批成功。
7. 导出所选用例 CSV 清单，仅包含类型、编号、名称、项目、分类/测试内容和详情路径。不是完整配置备份；不含认证信息、请求正文、变量、加密步骤。支持 Excel UTF-8，处理公式注入，响应禁止缓存。
8. 保留平台左侧菜单、内容区目录树、用例详情弹窗与单条归档，不更改缺陷、度量和平台管理分组。
9. 重复浏览器验收发现项目选择偶发读到旧值。运行配置是 `cached_db` 会话加进程内 `LocMemCache`，与多进程网页服务不匹配；改为数据库会话，不改表、不更改加密密钥，保留现有会话数据。这个判断结合了本机复现和配置核对；Django 官方也明确指出进程内缓存不适合多进程会话。[官方会话说明](https://docs.djangoproject.com/en/5.2/topics/http/sessions/)

本轮没有数据库模型变更、没有运行真实收费模型、没有触发用户业务自动化测试、没有提交或推送仓库。

## 四、分阶段顺序与验收标准

### A. 资产质量

- 个人筛选视图已实现并验证，但按用户反馈从用例库移除独立区域，优先保留目录树、搜索与类型筛选，减少页面负担；数据保留，暂不作为核心能力推进。参见[状态与历史说明](saved-case-views.md)。其余资产质量能力尚待实施。
- 三类用例统一版本展示和正式评审；公共步骤按版本引用。
- 验收：修改公共步骤能找出引用用例；已排队/历史执行快照不变；无权限成员不能批准；评审日志可追踪。

### B. 统一计划与执行追踪

- 迭代计划可关联手工执行、Web 套件运行、API 套件运行，不强制改成同一种执行器。
- 项目和发布版本口径一致；显示待执行/失败/阻塞/回归待验证，而非只给模糊的完成百分比。
- 验收：从计划跳到原始执行和失败证据；归档不重复计数；修复构建与回归构建可区分。

### C. 自动化工程化

- 优先 Web CI 触发、JUnit 结果导入、独立数据集复用，之后再做定时和多浏览器。
- 外部集成密钥、权限和幂等键必须独立设计；每次执行保留构建与来源。
- 验收：相同导入键不重复入库；非法/超大报告被拒绝；不能伪造别人的结果；导入不会自动执行脚本或自动批准发布。

### D. 团队协作与质量治理

- 明确项目角色、审批人、凭据使用范围、通知与审计；缺陷外部同步需逐平台验收。
- 门禁输出包含规则版本、证据快照和审批状态，外部发布流水线显式消费该结果。
- 验收：待批准和未通过门禁不能被正常发布路径忽略；特批有授权和理由；历史报告不被后续结果覆盖。

### E. 可演示可信度

- 一套独立演示数据：需求变更、三种用例、失败、缺陷、修复回归、报告；绝不用生产凭据。
- AI 标准评估集、备份恢复演练、基础并发和响应耗时测量。
- 验收：陌生面试官能按演示说明复现；指标有真实样本和分母，不写编造效率提升或准确率。

## 五、本轮验证记录

- 最终回归 **96 项全部通过**，包含 23 项新增检查、原有首页、共享目录、三类用例和 AI 草稿流程，以及会话一致性验证。
- 真实 Chromium 页面验收通过：混合类型批量归档/移出目录、CSV 文件下载及内容、父子目录与详情弹窗、从工作台真实按钮切换项目仍留在工作台、计划/运行默认筛选、全部用例分页；未捕获页面 JavaScript 异常。
- 此前单次浏览器通过不能证明项目选择稳定；重复验收复现了旧会话缓存问题。修复后连续交替访问工作台与计划/运行页面，4 轮计划、4 轮运行及穿插工作台均保持选中项目，最终独立浏览器验收通过。同期有一次浏览器等待 DOM 加载超时，服务器对应首页已在 244 ms 返回 200；之后独立复验通过，不据此宣称压力测试通过。
- 验收使用唯一命名临时产品、用例、目录及临时登录会话；自动清理完成，剩余验收产品数为 0。未调用真实模型、未触发用户业务接口或 Web 用例执行。
- 本轮四个 Python 模块通过 flake8；模型迁移检查显示无变更；网页容器健康，登录后验收页面返回 200，未登录首页返回正常的 302 登录跳转。
- 运行配置保留原有 `/Kiwi/tcms/node_modules` 目录缺失警告；页面使用镜像中的既有资源，已验收页面正常加载。这个警告不是“所有检查零告警”。远程 GitHub CI 本轮未运行。
