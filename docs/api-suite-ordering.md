# 接口自动化套件顺序

- 接口脚本的新建、编辑表单不再填写全局执行顺序。
- APISuite.case_ids 是有序列表，每个套件独立保存排序。
- 套件和临时执行表单提交 ordered_case_ids；服务端检查类型、重复、所选集合、账号和项目归属，最多 20 条。
- 依赖变量和数据组校验遵循提交顺序。未提供前置提取变量时拒绝提交，不发送请求。
- 手动执行、定时执行和 Jenkins / CI 都使用同一个套件提交入口。
- 快照的 cases 按实际执行顺序保存，selection.ordered_case_ids 记录编排顺序；后续编辑不能覆盖历史快照。
- CI 同构建重试仍返回原执行；临时表单的同提交令牌不能复用于不同顺序。
- 重新执行默认恢复源快照的实际顺序，不采用现在的套件排序。

## 兼容与迁移

0039_suite_script_order 将旧套件列表转换为原执行器的 sequence / pk 顺序。不可用 ID 不会被静默移除；无效套件继续阻止执行。
APICase.sequence 暂时保留在数据库中，用于旧内部调用和 AI 草稿兼容，不再控制普通页面提交或套件运行。无需改写或删除旧快照。

## 验证

tcms.ai_assistant.test_suite_ordering 覆盖独立排序、表单保存与回显、变量依赖、数据组、定时、CI 幂等、源快照重跑、迁移和真实本地 HTTP 依赖链。
