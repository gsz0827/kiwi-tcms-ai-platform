# Web 自动化测试

本模块使用 Playwright Chromium 执行声明式步骤，不接受任意 Python 或 JavaScript 脚本。菜单包含用例管理、测试套件、执行任务；质量与缺陷、度量分析、平台管理的分组保持不变。

## 使用

1. 在“Web 自动化测试 → 用例管理”新建用例，填写产品、名称及步骤。支持打开页面、点击、输入、选择、勾选，以及元素可见、文本、网址和标题断言；每条用例至少一个断言。保存后在内容区左侧的共享目录中归档。
2. 新建套件，选择同一产品下当前账号的用例及测试站点。访问本机平台时，容器内地址是 `https://kiwi-web:8443`（仓库独立部署为 `https://web:8443`），本机自签名证书需勾选相应选项。不要使用带下划线的主机名，Django 会拒绝该请求。
3. 在套件中点击执行并确认，进入执行详情查看进度。失败结果提供步骤编号、错误类别和截图（截图成功时）。
4. 可取消排队/执行中的任务；已结束任务可基于原快照重新执行。重新执行可能再次提交表单，请使用测试环境。

## 数据与限制

- 用例、套件、运行及截图按账号隔离。用例步骤和运行快照使用与个人模型配置相同的加密密钥保存。
- 套件展开后最多 20 条执行（数据组数 × 用例数），每条最多 30 步；单步默认最长 10 秒、整轮最长约 5 分钟。每条用例使用独立浏览器上下文，可复制所属数据组的公共登录 Cookie 和本地存储；业务用例之间不互相传递后续变更。
- 仅提供 Chromium，暂不提供脚本录制、多浏览器矩阵、Web 定时任务或 CI 触发。
- Web 与接口用例复用手工测试的共享目录组件，三类目录独立。目录支持子目录、新建、重命名、删除、用例归档及详情弹窗；目录按产品共享，用例内容仍按原有账号权限隔离。旧 Web 路径通过迁移转成共享目录，删除目录不会删除用例。
- 目录预览与手工测试一样显示当前搜索范围的最近 20 条，用例全量列表在右侧分页显示。点击“查看此目录用例”会筛选右侧列表（包括子目录），也可查看未归档用例。
- 执行结束后可点击“归档报告 / 创建缺陷草稿”，选择有权限的同产品测试计划、同版本构建及状态映射；确认后建立独立测试运行、报告快照，并仅为勾选失败项创建缺陷草稿。不调用 AI，不自动批准报告。已有报告审批、导出、门禁、缺陷关联及回归入口可继续使用；不会自动重跑浏览器或自动关闭缺陷。
- 输入值不写入步骤日志，但失败截图可能含页面敏感信息，仅任务所有者可访问；不要在演示中使用生产账号。
- 后台只接收显式配置的 `WEB_TEST_ALLOWED_ORIGINS` 站点；浏览器服务只应访问受信任的测试站点，不能把它作为浏览公网任意地址的服务。必须用网络策略限制不受信任站点的出网，应用层地址检查不替代网络隔离。
- 浏览器通过 `WEB_TEST_BROWSER_WS` 连接，服务端与 Python Playwright 必须使用相同版本（当前固定 1.63.0）。服务无需向宿主机暴露端口。
- `web_worker` 原子领取任务；10 分钟未更新心跳的运行标为中断，不自动重放。

## 环境、登录与数据驱动

- 从 Web 页面顶部“测试环境与公共登录配置”新建环境，配置站点、加密环境变量和可选的公共登录/前置用例。套件中选择该环境后，套件原地址字段作为旧版本兼容，不再决定执行站点。
- 步骤定位器、输入值和断言值可用 `{{变量名}}` 引用环境变量；套件的“多组测试数据”填写 `[{"username":"user1"},{"username":"user2"}]`，每组覆盖同名环境变量，最多 10 组，展开总执行数最多 20。
- 每组先执行一次公共前置用例（至少一个断言），成功后复用其 Cookie 与 localStorage。前置失败时该组业务步骤不发送，结果标为失败并注明前置原因；由用户确认是否应建缺陷。
- 登录态只保存在单次执行内存中，不跨组、跨账号、跨任务复用。暂不复用 sessionStorage 或浏览器 IndexedDB。
- 数据和环境进入加密执行快照；编辑配置不影响已排队或历史任务。重新执行原快照仍使用原参数。
- 归档会增加独立的场景快照用例，不覆盖当前用例；同一来源最多归档一次。只有标题、状态、耗时和来源链接进入共享报告，配置与截图仍保留原权限。

## 部署与验证

开发部署使用 `Dockerfile.web-worker` 基于现有 Kiwi 镜像添加 Playwright 客户端；`Dockerfile.web-browser` 构建独立 Chromium 服务。需共享相同数据库与 Django SECRET_KEY。在应用启用后执行 `python manage.py migrate --noinput`，再启动 `python manage.py web_worker`。

仓库独立部署先执行 `docker compose -f docker-compose.ai.yml build web` 构建基础应用镜像，再执行 `docker compose -f docker-compose.ai.yml -f docker-compose.web.yml up -d --build`。浏览器软件源可通过 `WEB_DEBIAN_MIRROR` 调整；本机开发环境使用保留数据的 `kiwi-dev-platform` 部署覆盖文件。

模块测试：`python manage.py test tcms.web_testing --settings=tcms.settings.test --noinput`。端到端验收应实际运行通过和失败用例，并核对失败截图、账号隔离与取消行为。

Playwright 官方运行说明：https://playwright.dev/python/docs/docker
