# Web AI 用例生成

## 导航分工

- 需求与任务单：需求管理、任务单。
- 测试管理：三类用例总览的用例库、测试计划、执行任务。
- Web 自动化测试：Web 用例管理（含 AI 生成入口）、测试套件、执行任务。
- 接口自动化测试：接口管理、接口用例管理（含 AI 生成入口）、测试套件、执行任务。
- 质量与缺陷、度量分析、平台管理保留原有入口。

总用例库用于跨类型查找。编辑具体自动化用例、配置环境、组合套件、执行测试仍在相应自动化模块中完成。

## 使用流程

1. 在自己的模型设置中配置 AI 模型。未配置时提醒用户，不读取服务器默认模型。
2. 在 Web 用例管理选择产品，点击“AI 生成 Web 用例”。
3. 填写页面路径、实际定位器、操作流程和预期提示。真实凭据换成变量占位符，只声明变量名。
4. 提交后进入草稿页，查看后台 AIJob 的实际状态、阶段和进度；完成后自动显示草稿。
5. 逐条编辑草稿，核对原文依据、定位器、断言和问题，填写确认说明并复核。
6. 选择已复核草稿保存到 Web 用例库，之后仍可在普通用例编辑器中修改。
7. 把用例加入测试套件，配置执行环境和变量值，再单独发起执行。

进度是后台阶段进度，不是模型 token 生成百分比。模型调用期间保持等待阶段，并持续轮询任务状态。

## 数据与安全边界

- 新增 WebAIRequest/WebAIDraft 保存输入快照及人工复核状态；不改写已有 WebCase。
- 输入资料、最终可执行步骤通过现有加密组件保存；草稿输出保存在 JSON 字段中，请勿在草稿填写真实凭据。
- AI 模型、生成记录、草稿和用例严格按账号查询。共享目录不意味着共享账号凭据。
- 模型只输出受限的 action/selector/value 声明式步骤；不支持脚本和任意代码。
- 至少一个断言、可追溯的原文依据、已声明变量、相对页面路径和人工确认都是入库条件。
- 只读账号不能提交、复核或入库；后台生成与入库时重新检查账号状态。
- 提交 token 防重复；复核 revision 防旧页面覆盖；多条入库在同一事务内完成。
- 用户取消后不保存本次模型响应。重试已生成批次时复用草稿，避免重复生成和重复入库。
- 生成和入库均不会启动 WebRun 或访问业务页面；执行由用户另外确认。
- 模型服务异常的日志和任务提示采用脱敏文案。

## 部署与验证

迁移 `web_testing/0004_ai_drafts` 和 `ai_assistant/0031_web_generation_operation`，收集静态资源，并在没有运行中 AI 任务时重启 Web 与 AI Worker。

相关回归测试：`tcms.web_testing.test_ai_generation`、`tcms.web_testing.tests`、`tcms.ai_assistant.test_case_hub`、`tcms.ai_assistant.test_api_ai`。
模型响应与异常测试采用模拟调用，不消耗真实 AI 配额，不执行业务站点操作。
