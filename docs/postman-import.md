# Postman 集合导入

入口：接口自动化测试 → 自动化脚本 → 导入 Postman。按项目维护，复用用例库业务目录；没有新建第二套目录体系。

流程：上传 Collection v2 / v2.1 JSON → 预览支持范围和目录 → 勾选请求 → 导入待复核脚本 → 编辑并确认请求/状态码/断言 → 加入套件 → 选择环境执行。

- 原集合及嵌套文件夹映射到项目共享业务目录，接口脚本跟随业务用例的目录。
- 支持 HTTP 方法、相对路径、查询参数、请求头、JSON 请求体和普通 `{{变量名}}` 引用。源服务地址不会复制到脚本，执行环境负责提供地址。
- 不运行或自动转换 Postman JavaScript、断言、认证算法、动态变量、表单、文件或 GraphQL。预览标明需要人工处理的内容，不支持的请求不可选。
- 不导入集合/目录变量值和认证值；不保存带明文密码、令牌、Cookie 的请求。请使用环境参数和加密认证请求头。
- 默认状态码 200 仅为待复核占位，不表示已识别源断言。导入脚本必须明确人工确认后才能由手动、套件、定时或 CI 提交执行。
- 预览仅当前账号可访问、加密保存、20 分钟有效；导入完成清空预览内容。上传不会发送 HTTP 请求或调用 AI。
- 同账号同项目的同一文件重复上传/确认不会重复创建；只新建，不覆盖已有脚本。变更过的集合视为新来源，需要人工选择。
- 2 MB / 200 请求 / 10 层目录限制；重复查询参数、重复请求头、无效格式会明确拒绝，避免有损转换。

这是 Postman 集合互通，不是嵌入 Postman 或 Newman 执行器，也不是云端双向同步。

格式依据：[Postman v11 导出文档](https://learning.postman.com/v11/docs/getting-started/importing-and-exporting/exporting-data)、[Collection v2.1 Schema](https://schema.postman.com/json/collection/v2.1.0/docs/index.html)。新版 v3 YAML 不在本次支持范围内。
