# 项目审查与修复记录

审查日期：2026-09-25。

本次检查围绕实际业务闭环：需求变更、AI 分析与用例生成、人工复核、用例库、接口执行、定时套件、CI 报告、后台任务和部署健康检查。下面的“已修复”对应本次代码变更，能力边界单独列出。

## 已修复

| 问题 | 修复后的行为 |
| --- | --- |
| 模型生成期间修改需求，旧分析或用例可能保存到新版本下 | 保存前对比输入指纹；需求、规则快照或相关草稿变化时拒绝旧结果入库，提示重新生成 |
| 应用 AI 用例评审会覆盖后来人工编辑的内容 | 应用前检查原始标题、正文；不一致时保留人工修改并要求重新评审 |
| AI 草稿配置无效时表单可能抛出 KeyError | 在配置字段显示校验错误，保留输入，不创建用例 |
| 未验证的执行顺序参与排序，异常模型输出可能导致 500 | 先验证配置，再检查实际执行顺序与前置变量 |
| 已删除或修改的接口配置仍被当作有效前置步骤 | 导入时读取当前接口配置；已删除的配置不再提供变量；同序号按实际创建顺序校验 |
| 批量导入后的执行入口只预选最后一条用例 | 保留多个 `case` 参数，预选整批接口配置 |
| 为已有手工用例导入接口配置后类型标记不一致 | 同步自动化标记，并保留历史记录 |
| 生成失败或取消后列表仍显示“生成中” | 显示最新后台任务的真实状态 |
| 页面消息把用户输入当作 HTML 展示 | 普通消息自动转义；由 `format_html` 构造的可信链接继续正常显示 |
| 修改定时间隔后仍沿用旧的下次执行时间 | 间隔变更后从当前时间重新计算；无关编辑不会覆盖调度器已推进的时间 |
| 停用账号的排队 AI 任务仍可能调用模型 | 在调用前及阶段切换时检查账号；已结束任务不会再次调用模型 |
| 中断任务残留“等待中”的结果 | 结束未完成条目，保留已完成结果，明确说明请求可能已经发送，不自动重放 |
| JUnit 报告可能将取消、中断或空任务显示为无错误 | 添加执行完整性错误；JSON 中允许而 XML 禁止的字符会替换，保证 XML 可解析 |
| 模型服务错误正文可能包含密钥或需求内容 | 错误只保留状态码和操作提示；不把响应正文写入任务错误或调用日志 |
| 模型请求可能跟随重定向转发认证头 | 拒绝重定向，要求配置最终服务地址；响应大小限制为 4 MB |
| 数据库长期阻塞时就绪检查不断创建线程 | 每个进程最多一个未结束的数据库探测；拒绝无穷大、NaN 等超时设置 |
| NaN、Infinity 等非标准 JSON 值可能进入数据库或请求 | 在表单与用例校验阶段拒绝，而不是保存时出错 |

回归用例集中在 `tcms/ai_assistant/test_audit_regressions.py`，并继续运行原有 AI、自动化、调度和核心页面测试。模型响应使用受控替身；HTTP 重定向和接口自动化使用本地真实 HTTP 服务。没有调用用户配置的收费模型，也没有运行用户的业务接口。

## 仍需完善的能力

1. **AI 质量需要可重复的评估集。** 目前具有规则快照、原文依据、结构校验、人工复核和版本保护；这些机制不能证明模型正确理解了业务。应维护带人工标准答案的需求集，统计关键场景覆盖率、错误假设率、人工修改比例，并对比规则包和模型版本。本次未伪造准确率数据。
2. **接口自动化仍是声明式 HTTP 执行。** 当前支持 JSON 请求、状态码/字段/耗时断言、变量提取、Cookie、套件、定时与 CI。文件上传、脚本钩子、复杂断言、外部 pytest/Playwright 结果导入和性能压测并未实现，不应在简历中声称已有。
3. **异常停机仍需要明确恢复。** Worker 没有分布式任务租约；强制终止后需要使用恢复命令。业务请求是否产生副作用不能仅凭超时判断，所以本次保持不自动重放。若以后增加自动恢复，应先设计目标接口幂等和执行租约。
4. **团队共享需要单独定义权限。** 目前 AI 配置、规则包与接口执行配置主要按账号隔离。多人共用产品时，仍需明确谁可编辑规则、谁可使用认证信息、谁可触发执行；不宜直接去掉 owner 限制。
5. **全库测试存在已记录的隔离问题。** 上游 RPC 的 `serialized_rollback` 与其他事务测试混跑时可能重复恢复 guardian 匿名用户；运维文档提供独立 RPC 测试入口。本次专项回归通过不能替代所有上游模块、真实服务和浏览器的全量验证。
6. **部署仍需备份恢复演练。** 代码检查不能证明数据库卷、附件及加密密钥的备份可恢复。当前虚拟机使用自签证书，未自动启用 HSTS；正式域名部署应结合有效证书配置。

## 应用修改

本次没有数据库结构变更。重新构建应用镜像并启动服务即可加载修改：

```bash
docker compose --env-file .env -f docker-compose.ai.yml up --build -d
```

不要删除数据库卷，也不要重新生成已有 `KIWI_SECRET_KEY`。需要运行中的接口任务完成后再更新 Worker。
