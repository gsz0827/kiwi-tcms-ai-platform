# 业务场景优先的测试流程

## 主流程

需求 → AI 生成测试场景草稿 → 人工核对并确认 → 保存业务用例 → 按需配置 Web / 接口自动化 → 明确发起执行 → 查看结果并确认归档报告与缺陷。

- 测试管理 → 用例库和工作台的用例入口统一进入 `/ai/scenarios/`。
- 一条原生 TestCase 表达业务测试目标、前置条件、步骤和预期结果，不再按手工、Web、接口拆成三份业务列表。
- 同一条业务用例可以同时关联多份 Web 和接口自动化配置，也可以仅人工执行。配置存在不代表验证通过。
- Web 和接口专属菜单继续用于维护定位器、请求参数、断言、套件、环境和执行任务。

## 草稿与确认

- 需求生成入口保留“生成测试用例”按钮；生成的是可编辑的场景草稿，不是已验证的自动化脚本。
- 保存前必须勾选人工确认并选择本次需求的草稿。需求版本变化、需要更新的草稿以及不属于当前需求的草稿不能直接保存。
- 人工确认不是正式多人评审或审批；本次没有部署正式评审、签字或发布门禁新功能。
- Web AI 配置预填原业务用例内容，但仍需真实页面证据、定位器和草稿校验；接口 AI 配置仍需真实接口资料。不得仅根据用例描述宣称自动化可运行。
- 页面访问、用例保存、配置保存和 AI 草稿导入均不会自动执行目标系统。

## 目录与权限

- 业务用例使用原项目共享目录，保留右键新建/重命名/删除、用例与文件夹拖动、分界线调宽和点击用例查看详情。
- 项目共享目录不等于所有成员自动获得全部用例、配置或执行结果的权限。业务用例继续使用原有对象查看/修改权限。
- 模型配置、Web/API 配置和运行记录按账号隔离；业务用例详情只展示当前账号自己的自动化配置及结果。超级管理员也不会通过新页面获得其他账号的私有配置。
- 未配置模型仍应提示用户配置，不回退到服务器默认模型。

## 执行结果与缺陷

- 人工执行使用原生测试计划/执行任务；Web 和接口使用原有套件及执行确认页面。
- 新建 Web 运行在不可变快照中保存 `business_case_id`。历史运行不根据当前配置名称或后来修改的关联关系猜测业务用例身份。
- 用例详情扫描当前账号同项目最近 20 次 Web 运行，并展示最近 10 条接口结果和原生执行；这不是全量历史搜索。
- 自动化失败结果必须经已有归档页面明确确认，才发布到共享报告并生成所选缺陷草稿。私有配置不会因页面访问而公开。
- 发布后的业务追踪根据运行时用例身份和结果位置，关联原生执行、报告和缺陷；后来重新关联配置不会改变原执行身份。
- 归档生成的专用快照 TestCase 保留在数据库和报告中，但不作为重复业务用例出现在新的用例库。
