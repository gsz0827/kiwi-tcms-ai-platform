# 标准用例设计表格

## 字段与布局

参考常用平台的字段组织，而不是宣称存在所有团队必须使用的唯一模板：

- 基本信息：用例编号、名称、项目/所属模块、测试类型、优先级、用例状态、关联需求、编写人和创建时间。
- 设计内容：前置条件、测试数据、逐步操作、逐步输入数据、预期结果、备注。
- 步骤表格：序号 / 操作步骤 / 输入数据 / 预期结果。
- 实际结果、执行状态、执行人和执行时间属于执行记录；不复制成业务用例的固定预期。
- 不新增“后置条件”输入字段，也不生成该章节。

参考资料：

- [TestRail 的用例字段](https://support.testrail.com/hc/en-us/articles/14940939006740-Test-case-fields)
- [TestRail 的分步及实际结果模板](https://support.testrail.com/hc/en-us/articles/7101746388500-Separate-test-steps-and-test-results)
- [Qase 用例说明](https://docs.qase.io/en/articles/5563704-test-cases)

## 兼容与编辑

- 详情和列表预览使用同一个展示组件。读取原生 TestCase.text 解析已知 AI Markdown 格式，不根据后来变化的 AI 草稿覆盖正式用例。
- 查看详情不会改写正文、备注或历史。无法确定结构的自由文本保留，默认使用原文编辑，不猜测预期结果。
- 表格编辑可新增、删除及上移/下移步骤，最多 100 步。操作和预期结果必填；前置条件、数据及备注按实际情况填写。
- 表格编辑保存为兼容原生 Kiwi 的文本；已识别的 AI 编号、类型和来源说明可保留。未知内容保存在可编辑的补充原文区，不直接丢弃。
- 没有修改数据库结构，没有批量改写旧用例。修改仍使用原对象权限与原生历史记录。
- 表格/原文是两种独立编辑方式；已有未保存修改时切换方式会提示确认。
- HTML 和脚本内容自动转义，不以任意 HTML 直接渲染。

## 其他可读性改进

- 自动化配置卡片和明确的“我的配置”范围。
- 平台执行、接口结果、Web 套件状态改为表格；成功/失败有文字及颜色，不仅依赖颜色。
- 缺陷展示状态、严重程度、优先级、负责人；归档报告保留原入口。
- 长标题换行、较大的步骤正文、窄屏表格内部横向滚动，不撑宽整页。
- 新详情页的时间按现有账号显示时区转换，不改全局时间储存或其他页面。
